# 档案编研 - 验收

## 1. 验收范围

- 页面：档案编研
- 路径：`prototype/admin/compilation.html`
- 版本：静态高保真原型
- 验收依据：`档案编研-原型设计.md`、场景十、数据库表 `compilations`、`compilation_materials`、`archives`、`archive_files`

## 2. 功能验收项

| 验收项 | 验收标准 | 状态 |
|---|---|---|
| 后台统一壳层 | 页面包含左侧导航、顶部栏和管理后台内容区 | 通过 |
| 公共样式引用 | HTML 引用 `../common/css/base.css`、`components.css`、`shell.css` | 通过 |
| 编研状态展示 | 展示草稿、已生成、已入库等 `compilations.status` 状态 | 通过 |
| 素材引用 | 页面展示素材筛选和引用列表，说明只记录引用关系 | 通过 |
| 正文生成 | 点击“生成正文文件”后状态变为已生成，正文文件标记为成功 | 通过 |
| 纯电子入库 | 点击“确认纯电子入库”后生成正式档号，展示 `source_type=compilation` 与纯电子载体 | 通过 |
| 素材保护 | 页面明确不复制素材正文，不改变素材档案元数据、密级和公开状态 | 通过 |

## 3. 交互验收项

| 验收项 | 验收标准 | 状态 |
|---|---|---|
| 新建成果 | 点击后进入草稿编辑状态并给出反馈 | 通过 |
| 保存草稿 | 点击后提示草稿已保存，状态仍为 `draft` | 通过 |
| 添加素材 | 点击后素材列表新增一条引用，素材数量同步更新 | 通过 |
| 查看详情 | 列表中“查看/详情”按钮可载入对应成果并给出只读或可编辑反馈 | 通过 |
| 入库前校验 | 未生成正文文件时点击入库会提示先生成正文文件 | 通过 |
| 入库反馈 | 入库成功后状态、档号和统计数字同步变化 | 通过 |

## 4. 启发式评估验收

1. 系统状态可见性：状态标签、指标卡和反馈提示清晰，符合。
2. 系统与现实世界匹配：使用编研、素材、档号、纯电子等业务语言，符合。
3. 用户控制与自由：草稿保存和入库确认分离，符合。
4. 一致性与标准：复用公共后台壳层和按钮状态，符合。
5. 错误预防：正文未生成禁止入库，符合。
6. 识别而非记忆：素材、正文、入库口径同屏可见，符合。
7. 灵活性与效率：支持状态筛选和素材快速添加，符合原型要求。
8. 美观与简约设计：布局分区清楚，无无关模块，符合。
9. 帮助用户识别和修复错误：入库阻断提示指向具体缺失步骤，符合。
10. 帮助与文档：关键业务边界已在页面业务提示中呈现，符合。

## 5. 问题记录

无阻断问题。静态原型中的筛选、生成文件和入库为前端模拟，后续实现需接入正式接口和权限校验。

## 6. 验收结论

通过。页面满足“编研成果来源为 `compilation` 且纯电子入库”的业务口径，并保持素材引用与正式档案元数据隔离。
