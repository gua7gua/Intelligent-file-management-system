# 用户管理 - 验收

## 1. 验收范围

- 页面：用户管理
- 路径：`prototype/admin/user-management.html`
- 版本：静态高保真原型
- 验收依据：`用户管理-原型设计.md`、场景十四、数据库表 `organizations`、`fonds`、`users`、`roles`、`user_roles`、`audit_logs`

## 2. 功能验收项

| 验收项 | 验收标准 | 状态 |
|---|---|---|
| 后台统一壳层 | 页面包含左侧导航、顶部栏和管理后台内容区 | 通过 |
| 公共样式引用 | HTML 引用 `../common/css/base.css`、`components.css`、`shell.css` | 通过 |
| 用户概览 | 展示内部账号、公众账号、禁用账号、系统管理员数量 | 通过 |
| 用户列表 | 展示登录名、姓名、单位、角色、数据范围、密级上限和状态 | 通过 |
| 账号编辑 | 提供登录名、姓名、类型、电话、单位、部门、数据范围和密级上限字段 | 通过 |
| 角色关系 | 支持勾选预设角色，模拟写入 `user_roles` | 通过 |
| 组织与全宗 | 页面展示组织和全宗基础关系 | 通过 |
| 系统管理员边界 | 明确不默认查看档案正文和电子文件，不替代业务审批 | 通过 |
| 审计留痕 | 明确用户禁用、重置密码、角色变更写入审计日志 | 通过 |

## 3. 交互验收项

| 验收项 | 验收标准 | 状态 |
|---|---|---|
| 新建用户 | 点击后清空编辑区并进入新建状态 | 通过 |
| 保存用户 | 选择角色后可新增示例用户并更新内部账号数量 | 通过 |
| 角色校验 | 未选择角色时提示至少选择一个预设角色 | 通过 |
| 编辑用户 | 点击编辑后载入对应登录名 | 通过 |
| 重置密码 | 点击后提示生成密码重置记录 | 通过 |
| 禁用账号 | 点击后账号状态变为禁用，禁用账号数量更新 | 通过 |
| 筛选用户 | 点击筛选后提示实际权限以后端接口鉴权为准 | 通过 |
| 动态行操作 | 新增保存的用户行同样可通过事件委托响应编辑操作 | 通过 |

## 4. 启发式评估验收

1. 系统状态可见性：账号状态、角色、数据范围和统计数清楚，符合。
2. 系统与现实世界匹配：使用组织、全宗、密级上限等术语，符合。
3. 用户控制与自由：保存前可调整字段，符合。
4. 一致性与标准：复用后台壳层、表单、表格和状态标签，符合。
5. 错误预防：保存时要求至少一个角色，符合。
6. 识别而非记忆：角色代码和中文入口同屏展示，符合。
7. 灵活性与效率：支持多角色选择和列表筛选，符合。
8. 美观与简约设计：用户、组织、全宗和边界说明分区清楚，符合。
9. 帮助用户识别和修复错误：角色缺失时给出明确提示，符合。
10. 帮助与文档：权限边界和审计留痕提示清晰，符合。

## 5. 问题记录

无阻断问题。静态原型中的新增、禁用和重置为前端模拟，后续实现需接入用户、角色、组织、全宗和审计接口。

## 6. 验收结论

通过。页面满足“用户管理服务系统管理员，不替代档案业务审批”的业务边界。
