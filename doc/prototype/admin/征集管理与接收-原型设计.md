# 征集管理与接收-原型设计

## 1. 页面概述

- 页面名称：征集管理与接收
- 所属门户：管理后台
- 页面路径：`prototype/admin/collection.html`
- 使用角色：档案管理员（后台）、档案管理员（前台）
- 页面目标：处理公众征集清单的联系判断、到馆接收、在线协议记录校验、电子文件上传匹配、回执导出，并将已接收条目交给后续入库流程。

## 2. 业务场景归属分析

- 所属业务场景：场景二“社会征集与捐赠”。
- 上游输入：公众在 `public/collection.html` 提交的征集清单，进入 `intake_batches(source_type = collection, status = pending_contact)`。
- 下游消费：后台联系后流转为待接收或已拒绝；前台验收后流转为已接收或部分接收；已接收条目进入后台 AI 补全与入库页面。
- 涉及实体：`intake_batches`、`intake_items`、`staging_files`、`business_attachments`、`audit_logs`。
- 状态节点：待联系 -> 待接收 / 已拒绝；待接收 -> 已接收 / 部分接收 / 已拒绝；条目待验收 -> 已接收 / 已回退；后续进入待入库。

## 3. 用户与操作分析

- 档案管理员（后台）主路径：查看待联系清单；记录联系结果和约定到馆时间；拒绝不符合征集方向的整批清单。
- 档案管理员（后台）异常路径：公众待处理超过限制或材料方向不符时填写拒绝理由；联系失败时保留待联系备注。
- 档案管理员（前台）主路径：调取待接收清单；核对条目；按需展开上传区处理电子介质文件；校验提交时的在线协议记录；导出接收回执。
- 档案管理员（前台）异常路径：条目不合格时标记回退并填写原因；缺少在线协议同意记录时禁止完成接收。
- 操作结果：状态流转、附件记录、暂存文件匹配记录、回执导出、审计日志记录。

## 4. 页面布局说明

- 统一后台壳层：左侧导航、顶部栏、内容区。
- 顶部概览：待联系、待接收、今日到馆、协议记录异常数量。
- 主列表：按状态筛选征集批次，展示清单号、捐赠人、条目数、约定时间和当前处理角色；列表与详情各自滚动。
- 详情区：联系处理、到馆验收、在线协议记录、可折叠上传匹配区和条目验收区块；条目表格支持独立滚动。
- 右侧流程：展示状态流转和当前操作结果。

## 5. 交互逻辑说明

- 状态筛选切换不同批次列表；选择批次后详情区刷新。
- 后台管理员点击“约定到馆”后填写时间，批次状态改为待接收。
- 后台管理员点击“拒绝征集”必须填写拒绝理由，批次状态改为已拒绝。
- 前台管理员在待接收状态下展开上传区，选择或拖拽捐赠电子文件后生成暂存匹配卡片；再标记条目接收或回退，系统校验在线协议同意记录；完成接收后状态按条目汇总为已接收或部分接收。
- 导出回执仅在已接收或部分接收后可用，回执包含接收条目和回退原因。

## 6. 启发式自查记录

1. 系统状态可见性：批次状态、条目验收状态、协议状态和回执状态可见。
2. 系统与现实世界匹配：使用“约定到馆”“在线协议”“接收回执”等业务语言。
3. 用户控制与自由：联系、拒绝、接收等关键操作都有确认区域。
4. 一致性与标准：复用后台壳层、导航、卡片、表格、标签和按钮。
5. 错误预防：拒绝需理由，完成接收需在线协议记录，回退条目需原因。
6. 识别而非记忆：流程节点和当前批次详情同时展示。
7. 灵活性与效率：状态标签筛选、批次详情联动、上传匹配和独立滚动减少查找成本。
8. 美观与简约设计：页面聚焦征集联系和接收，不处理入库上架。
9. 帮助用户识别错误：缺少在线协议记录或回退原因时提示。
10. 帮助与文档：流程侧栏说明已接收条目进入后续入库。
