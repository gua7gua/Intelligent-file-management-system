# 全宗管理 - 验收

## 1. 验收范围

- 页面：全宗管理
- 文件：`prototype/admin/fonds.html`
- 版本：静态交互原型
- 验收依据：`prototype/admin/全宗管理-原型设计.md`、`prototype/原型交互设计规范.md`、`new-doc/业务场景.md` 场景十八。

## 2. 功能验收项

| 编号 | 验收项 | 验收标准 | 状态 |
|------|--------|----------|------|
| F-01 | 统一后台壳层 | 页面使用顶部栏、左侧导航栏和内容区布局 | 通过 |
| F-02 | 全宗概览 | 展示全宗总数、启用全宗、归档档案量和档案盒数量 | 通过 |
| F-03 | 筛选查询 | 支持按关键词、所属单位和关联状态筛选全宗列表 | 通过 |
| F-04 | 全宗列表 | 展示全宗号、全宗名称、所属单位、归档档案数量、档案盒数量和状态 | 通过 |
| F-05 | 新建全宗 | 新建时全宗号可输入，保存校验全宗号、全宗名称和所属单位 | 通过 |
| F-06 | 编辑全宗 | 编辑已有全宗时全宗号只读，名称、所属单位和说明可修改 | 通过 |
| F-07 | 删除/停用规则 | 有归档档案或档案盒时阻止删除并模拟停用；无关联数据时可模拟删除 | 通过 |
| F-08 | 关联数据展示 | 详情区展示门类分布和最近入库记录 | 通过 |

## 3. 交互验收项

| 编号 | 验收项 | 验收标准 | 状态 |
|------|--------|----------|------|
| I-01 | 操作反馈 | 查询、保存、校验失败、停用、取消均有即时提示 | 通过 |
| I-02 | 错误预防 | 全宗号为空、名称为空、未选单位、全宗号重复均阻止保存 | 通过 |
| I-03 | 选中联动 | 点击列表行刷新右侧详情、门类分布和最近入库 | 通过 |
| I-04 | 权限边界 | 页面说明全宗不直接关联移交清单，入库时才写入正式档案归属 | 通过 |
| I-05 | 导航关系 | 提供组织维护入口，当前页面导航高亮为全宗管理 | 通过 |

## 4. 启发式评估验收

| 原则 | 评估结论 | 状态 |
|------|----------|------|
| 系统状态可见性 | 状态标签、统计卡和 toast 提示可见 | 通过 |
| 系统与现实世界匹配 | 使用全宗号、所属单位、归档档案、档案盒等业务术语 | 通过 |
| 用户控制与自由 | 新建和编辑可取消，删除前按关联数据判断 | 通过 |
| 一致性与标准 | 复用公共后台样式、按钮、表格和表单 | 通过 |
| 错误预防 | 全宗号唯一、所属单位必填、编辑时全宗号只读 | 通过 |
| 识别而非记忆 | 详情区持续展示当前全宗与关联数量 | 通过 |
| 灵活性与效率 | 常用筛选和快速新建入口位于首屏 | 通过 |
| 美观与简约设计 | 概览、筛选、列表、详情和规则提示分区清晰 | 通过 |
| 帮助识别和修复错误 | 校验失败提示具体缺失或重复字段 | 通过 |
| 帮助与文档 | 页面内说明全宗与入库、权限过滤、组织维护关系 | 通过 |

## 5. 问题记录

| 编号 | 描述 | 严重程度 | 建议 |
|------|------|----------|------|
| W-01 | 静态原型中的停用和删除仅模拟前端状态，不持久化 | 低 | 正式开发时接入后端接口并写入 `audit_logs` |
| W-02 | 组织单位列表为静态示例 | 低 | 正式开发时读取 `organizations.status = active` 的单位 |

## 6. 验收结论

页面通过本轮原型验收。正式开发需补充后端唯一性校验、组织状态校验、关联档案和档案盒删除保护、停用状态持久化及审计日志写入。
