# 档案管理 - 原型设计

## 1. 页面概述

- 页面名称：档案管理
- 所属门户：管理后台
- 页面路径：`prototype/admin/archive-management.html`
- 使用角色：档案管理员（后台）
- 页面目标：查询正式档案、查看详情、编辑非受保护元数据，并从详情发起密级调整或开放调整审批。

## 2. 业务场景归属分析

所属业务场景为场景三“档案管理（整理、密级调整、开放调整）”。页面处理已经写入 `archives` 的正式档案，不处理移交/征集清单预入库数据。

涉及数据实体：
- `archives`：档号、题名、责任者、形成日期、分类、来源、载体、保管期限、密级、公开状态、生命周期、借阅状态。
- `archive_files`：预览和下载文件记录。
- `archive_tags`、`tags`：标签维护。
- `approval_requests`：密级调整、开放调整申请。
- `archive_change_logs`、`audit_logs`：元数据编辑与审批留痕。

状态节点：
- 正式档案：已入库未上架、正常、借出、盘点中、待销毁、已销毁。
- 审批单：待审批、已退回、已批准。
- 开放状态：公开、不公开；密级：非密、秘密、机密、绝密。

上下游关系：
- 上游：待入库与上架页面生成正式档案。
- 下游：内部/公众检索、借阅、盘点、鉴定、销毁、审批工作台。
- 密级和开放调整提交后进入 `prototype/admin/approval.html`，通过后字段才生效。

## 3. 用户与操作分析

| 角色 | 操作 | 路径类型 | 结果 |
|------|------|----------|------|
| 后台管理员 | 按分类、年度、密级、公开状态、载体、状态筛选档案 | 主路径 | 查询正式档案列表 |
| 后台管理员 | 查看档案详情 | 主路径 | 展示完整元数据、文件和状态 |
| 后台管理员 | 编辑题名、责任者、形成日期、分类、标签、摘要 | 主路径 | 写入 `archive_change_logs` |
| 后台管理员 | 发起密级调整 | 主路径 | 填凭证档号、调整后密级、理由，生成审批单 |
| 后台管理员 | 发起开放调整 | 主路径 | 填凭证档号、调整后开放状态、理由，生成审批单 |
| 后台管理员 | 尝试修改受保护字段 | 异常路径 | 页面展示只读，提示需走审批或业务流程 |

## 4. 页面布局说明

- 左侧为固定五大类分类树，不提供增删。
- 中部上方为筛选表单，中部下方为档案列表。
- 右侧详情抽屉展示可编辑元数据、受保护字段、文件操作和审批申请面板。
- 顶部说明“普通编辑和 AI 不覆盖受保护字段”。

## 5. 交互逻辑说明

1. 点击分类树或筛选条件后刷新列表。
2. 点击档案行后右侧详情抽屉更新。
3. 保存元数据时只保存题名、责任者、形成日期、分类、标签、摘要。
4. 密级/开放调整必须输入凭证档号和理由；页面模拟校验凭证存在、未销毁并与目标档案来源匹配。
5. 提交后显示“已生成审批单”，目标字段在审批通过前不变化。

## 6. 启发式自查记录

| 原则 | 自查结论 |
|------|----------|
| 系统状态可见性 | 筛选、详情、保存和审批提交都有反馈。 |
| 现实世界匹配 | 使用全宗、门类、档号、密级、开放状态等业务语言。 |
| 用户控制与自由 | 元数据编辑可取消，审批申请提交前可修改。 |
| 一致性与标准 | 复用后台导航、表格、抽屉、按钮和状态标签。 |
| 错误预防 | 受保护字段只读；审批凭证档号必填。 |
| 识别而非记忆 | 可编辑字段与受保护字段分区展示。 |
| 灵活性与效率 | 分类树和多条件筛选并用。 |
| 美观与简约 | 详情只展示整理和审批发起所需信息。 |
| 错误识别与恢复 | 凭证缺失、理由缺失时提示具体原因。 |
| 帮助与文档 | 页面说明解密不等于自动公开。 |
