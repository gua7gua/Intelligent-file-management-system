# 借阅审批 - 原型设计

## 1. 页面概述

- 页面名称：借阅审批
- 所属门户：管理后台
- 页面路径：`prototype/admin/borrow-approval.html`
- 使用角色：档案管理员（后台）、档案管理员（前台）
- 页面目标：完成纸质档案借阅申请审核、凭证导出提示、到馆核验、确认出库和归还检查闭环。

## 2. 业务场景归属分析

所属业务场景为场景八“借阅审批”。内部查阅者在检索页提交借阅申请，后台管理员审核是否可借，前台或后台管理员到馆核验凭证并确认出库和归还。

涉及数据实体：
- `borrow_requests`：申请号、档案、借阅人、理由、时长、到馆时间、状态、审批、凭证、出库、归还字段。
- `archives`：`lifecycle_status`、`loan_status`、`carrier_status`。
- `inventory_tasks`：借阅审批需检查进行中的盘点范围。
- `audit_logs`：申请、审批、出库、归还记录。

状态节点：
- 借阅申请：已申请、已拒绝、已批准、凭证已导出、已出库、已归还、逾期、异常归还。
- 正式档案：正常、借出、盘点中。

上下游关系：
- 上游：内部档案检索利用页提交申请。
- 下游：审批通过后内部查阅者导出凭证；到馆核验后档案状态变为借出；归还检查通过后恢复正常。

## 3. 用户与操作分析

| 角色 | 操作 | 路径类型 | 结果 |
|------|------|----------|------|
| 后台管理员 | 查看待审批申请 | 主路径 | 看到借阅理由、时长、到馆时间和档案状态 |
| 后台管理员 | 审批通过 | 主路径 | 借阅申请状态变为已批准，通知申请人导出凭证 |
| 后台管理员 | 审批拒绝 | 异常路径 | 填写拒绝理由，申请状态变为已拒绝 |
| 前台/后台管理员 | 到馆核验凭证 | 主路径 | 凭证有效且单位已盖章后可确认出库 |
| 前台/后台管理员 | 确认出库 | 主路径 | 记录借出时间、应还时间、经办人，档案借出 |
| 前台/后台管理员 | 确认归还 | 主路径 | 记录归还检查结果，档案恢复正常 |
| 前台/后台管理员 | 异常归还 | 异常路径 | 填写缺页、破损、涂改等说明 |

## 4. 页面布局说明

- 后台壳层和统一导航。
- 顶部指标展示待审批、已批准未出库、借出中、逾期/异常。
- 左侧为借阅申请队列和状态标签。
- 右侧详情分为审批信息、可借检查、凭证核验、出库与归还。
- 管理员可见架位；内部查阅者页面不展示架位，本页用于管理员出库。

## 5. 交互逻辑说明

1. 点击申请队列切换详情。
2. 审批通过前检查档案为纸质相关、生命周期正常、未借出、未命中进行中的盘点范围。
3. 借阅凭证不是出库记录；只有到馆核验并点击确认出库后档案才变为借出。
4. 归还时必须填写归还检查结果；异常归还需补充说明。
5. 审批拒绝必须填写拒绝理由。

## 6. 启发式自查记录

| 原则 | 自查结论 |
|------|----------|
| 系统状态可见性 | 申请状态、可借检查、出库/归还状态可见。 |
| 现实世界匹配 | 使用借阅凭证、单位盖章、到馆核验、应还时间等业务语言。 |
| 用户控制与自由 | 审批、出库、归还分步骤，误操作前有确认。 |
| 一致性与标准 | 复用后台导航、卡片、状态、表单和按钮。 |
| 错误预防 | 盘点中、已借出、未上架档案不可通过审批。 |
| 识别而非记忆 | 审批检查项逐条展示。 |
| 灵活性与效率 | 状态标签快速筛选待审批、当前借阅和归还。 |
| 美观与简约 | 页面围绕借阅闭环四步组织。 |
| 错误识别与恢复 | 拒绝和异常归还均需填写说明。 |
| 帮助与文档 | 页面说明凭证不是出库记录。 |
