# 档案编研 - 原型设计

## 1. 页面概述

- 页面名称：档案编研
- 所属门户：管理后台
- 页面路径：`prototype/admin/compilation.html`
- 使用角色：档案管理员（后台）
- 设计依据：`new-doc/业务场景.md` 场景十、`new-doc/数据库设计.md` 中 `compilations`、`compilation_materials`、`archives`、`archive_files`，以及 `module-portal-overview.puml`、`data-flow.puml`。

## 2. 业务场景归属分析

本页面属于“档案编研”场景，承接正式档案检索与素材引用能力，产出来源为 `compilation` 的正式档案和正文电子文件记录。页面不改变被引用素材档案的题名、密级、开放状态、保管期限或其他受保护字段。

上游输入为已有正式档案的元数据和管理员筛选结果；页面内保存编研草稿、素材引用关系和富文本正文；下游消费为正式档案管理、检索利用和保存备份。入库后写入 `archives.source_type = compilation`，`archives.carrier_status = electronic`，并在 `archive_files` 中生成 `file_role = compilation_body` 的正文文件。

涉及状态节点：

- 编研成果：`draft`、`generated`、`archived`
- 正式档案：纯电子编研成果入库后为 `normal`
- 正式电子文件：生成正文文件后随入库写入正式文件记录

## 3. 用户与操作分析

角色：档案管理员（后台）。

主路径操作：

- 新建编研成果，填写标题、类型、时间范围、关键词和摘要，结果为 `compilations.status = draft`
- 添加素材，通过题名、分类、年度、标签筛选正式档案，结果为写入 `compilation_materials`
- 编辑富文本正文并保存草稿，结果为更新 `content_html`
- 生成正文文件，结果为生成正文附件并将状态置为 `generated`
- 确认入库，结果为生成正式档号、正式档案和编研正文文件记录，状态置为 `archived`

异常路径操作：

- 素材无权限或已销毁：禁止引用并提示原因
- 正文未生成：禁止入库
- 入库元数据缺失：高亮缺失字段并停留在入库确认区

## 4. 页面布局说明

页面使用管理后台统一壳层：左侧导航、顶部角色栏、内容区。内容区分为状态指标、编研成果列表、新建/编辑区、素材引用区、正文预览与入库确认区。

关键区域：

- 成果状态卡片：展示草稿、已生成、已入库和本月新增数量
- 成果列表：展示编研编号、题名、类型、状态、素材数、正文文件和入库档号
- 素材选择：按题名、分类、年度、标签筛选，只引用档号和引用说明
- 正文与入库：展示正文文件状态、入库元数据和纯电子入库约束

## 5. 交互逻辑说明

点击“新建编研成果”打开编辑区并进入草稿状态；点击“添加素材”模拟加入素材列表；点击“保存草稿”更新页面提示；点击“生成正文文件”将当前成果状态更新为“已生成”；点击“确认纯电子入库”后生成示例正式档号，状态更新为“已入库”。

入库前校验：必须有标题、摘要、至少一个素材引用和正文文件。页面以业务提示明确：素材只记录引用关系，不复制正文，不改变素材档案；编研成果入库后来源为 `compilation`，载体状态为纯电子。

## 6. 启发式自查记录

1. 系统状态可见性：通过状态标签、指标卡和操作反馈展示草稿、生成、入库进度。
2. 系统与现实世界匹配：使用“素材”“正文文件”“正式档号”“纯电子档案”等档案业务术语。
3. 用户控制与自由：编辑区提供保存草稿和取消选择，入库前保留确认步骤。
4. 一致性与标准：复用后台导航、表格、状态标签和按钮样式。
5. 错误预防：正文未生成或元数据缺失时禁止入库。
6. 识别而非记忆：素材列表、入库字段和来源口径在同屏可见。
7. 灵活性与效率：提供筛选条件、批量素材勾选和快捷状态切换。
8. 美观与简约设计：区域按“成果、素材、正文、入库”分组，避免无关说明。
9. 帮助用户识别和修复错误：错误提示说明缺失项和下一步操作。
10. 帮助与文档：关键业务边界以页面提示呈现，复杂流程不依赖外部记忆。
