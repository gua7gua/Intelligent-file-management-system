# 数据研判 - 原型设计

## 1. 页面概述

- 页面名称：数据研判
- 所属门户：管理后台
- 页面路径：`prototype/admin/data-analysis.html`
- 使用角色：档案管理员（后台）
- 设计依据：`new-doc/业务场景.md` 场景十二、`new-doc/AI交互架构.md`、`new-doc/数据库设计.md` 中 `analysis_tasks`、`analysis_items`、`archives`、`archive_change_logs`，以及 `ai-interaction.puml`、`data-flow.puml`。

## 2. 业务场景归属分析

本页面属于“统计与研判”的数据质量研判部分。规则扫描先检查正式档案元数据缺失项，AI 再基于题名、责任者、形成日期、分类、标签、摘要等元数据生成候选异常建议。AI 不读取电子文件正文，不直接写库，不覆盖受保护字段。

上游输入为正式档案元数据和扫描规则；页面内生成 `analysis_tasks` 和 `analysis_items`；下游消费为档案管理页面的人工补充、分类调整或待处理清单。采纳或不采纳建议只改变研判建议处理状态或生成后续处理入口，不在本页直接修改 `archives`。

涉及状态节点：

- 研判任务：`running`、`completed`、`failed`
- 研判建议：`pending`、`adopted`、`rejected`
- 正式档案：本页只读展示，不直接改变生命周期、密级、公开状态或分类字段

## 3. 用户与操作分析

角色：档案管理员（后台）。

主路径操作：

- 选择扫描范围和任务类型，点击开始扫描，结果为创建 `analysis_tasks`
- 查看规则扫描和 AI 建议 JSON，结果为展示候选异常
- 点击条目进入详情后采纳、不采纳或生成待补充清单，结果为更新 `analysis_items.status`
- 跳转到档案管理页面处理元数据补充，结果由正式业务接口和权限校验执行

异常路径操作：

- AI 不可用：只执行规则扫描并生成缺失字段建议
- 建议命中受保护字段：后端白名单过滤后剥离，不在页面展示为可直接写入项
- 档案状态为已销毁：只展示风险提示，不提供处理入口

## 4. 页面布局说明

页面使用管理后台统一壳层。内容区分为扫描控制、任务状态、建议列表、条目详情、AI JSON 结果、采纳队列和白名单边界提示。

关键区域：

- 扫描控制：选择扫描范围、任务类型和每批数量
- 任务状态：展示任务号、状态、扫描数量、异常建议数
- 建议列表：展示档号、题名、问题类型、问题描述、建议动作和处理状态
- AI JSON：展示 `ruleType = dataAnalysis` 的结构化候选结果
- 后续处理：采纳后生成待补充清单或跳转档案管理

## 5. 交互逻辑说明

点击“开始扫描”后任务状态变为执行中，再模拟完成并展示异常建议。列表只展示处理状态和详情入口；进入条目详情后点击“采纳”将状态改为“已采纳”并加入待处理队列，点击“不采纳”将状态改为“已不采纳”。点击“生成待补充清单”输出后续处理反馈，不直接修改正式档案。

页面展示 AI 输出必须经过 JSON 提取、`ruleType` 校验、字段白名单校验、枚举值校验、权限和状态校验。受保护字段包括密级、保管期限、公开状态、允许数字化、档号、架位、销毁状态，本页不提供直接覆盖入口。

## 6. 启发式自查记录

1. 系统状态可见性：扫描状态、建议数量、处理状态明确展示。
2. 系统与现实世界匹配：使用缺失字段、分类冲突、标签建议等业务语言。
3. 用户控制与自由：建议可采纳、不采纳或跳转处理，不强制执行。
4. 一致性与标准：复用后台壳层、AI 结果框、状态标签和表格。
5. 错误预防：AI 建议不直接改库，受保护字段明确禁止。
6. 识别而非记忆：白名单边界、JSON 和建议列表同屏展示。
7. 灵活性与效率：支持扫描范围和任务类型选择。
8. 美观与简约设计：控制区、结果区和处理区分离。
9. 帮助用户识别和修复错误：异常建议包含问题描述和建议动作。
10. 帮助与文档：AI 安全边界以页面提示呈现。
