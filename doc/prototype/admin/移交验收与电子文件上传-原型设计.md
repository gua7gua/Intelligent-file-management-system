# 移交验收与电子文件上传 - 原型设计

## 1. 页面概述

- 页面名称：移交验收与电子文件上传
- 所属门户：管理后台
- 页面路径：`prototype/admin/transfer-reception.html`
- 使用角色：档案管理员（前台）
- 页面目标：前台管理员调取待移交清单，清点纸质实物，上传 U 盘电子文件，按文件名匹配清单条目，处理匹配异常和四性检查结果，确认接收或部分接收并导出回执。

## 2. 业务场景归属分析

- 所属业务场景：业务部门移交档案的“前台清点与电子文件上传”阶段。
- 涉及数据实体：`intake_batches`、`intake_items`、`staging_files`、`business_attachments`、四性检查记录。
- 批次状态：待移交 -> 已接收 / 部分接收 / 已拒绝。
- 条目状态：待验收 -> 已接收 / 已回退。
- 暂存电子文件状态：未上传 -> 暂存 -> 匹配成功 / 匹配异常；入库后才变为已归档。
- 数据流向：
  - 上游：移交单位提交待移交清单并线下携带纸质原件、U 盘和签字清单到馆。
  - 当前页：前台管理员核对纸质档案、上传电子文件、记录验收说明和回退原因。
  - 下游：已接收条目进入后台“待入库与上架”页面；回退条目写入回执并由移交单位下次新建清单补交。
- 权限边界：前台管理员可编辑验收记录、文件匹配结果、回退原因和回执，不生成正式档号、不做 AI 补全、不分配架位。

## 3. 用户与操作分析

| 角色 | 操作 | 路径类型 | 结果 |
|------|------|----------|------|
| 档案管理员（前台） | 查询待移交清单 | 主路径 | 查看待验收批次 |
| 档案管理员（前台） | 打开清单详情 | 主路径 | 查看清单级信息和条目 |
| 档案管理员（前台） | 标记纸质验收通过 | 主路径 | 条目保持可接收状态 |
| 档案管理员（前台） | 上传 U 盘电子文件 | 主路径 | 写入暂存文件并生成匹配和四性检查结果 |
| 档案管理员（前台） | 人工确认重复匹配 | 异常路径 | 将暂存文件关联正确条目 |
| 档案管理员（前台） | 回退异常条目 | 异常路径 | 条目变为已回退，必须填写回退原因 |
| 档案管理员（前台） | 确认接收 | 主路径 | 批次变为已接收或部分接收 |
| 档案管理员（前台） | 导出接收回执 | 主路径 | 生成回执 PDF，包含已接收条目和回退原因 |

## 4. 页面布局说明

- 管理后台壳层：统一左侧导航和顶部栏。
- 左侧导航：管理概览、移交验收、待入库与上架、档案管理等后台入口。
- 内容区：
  - 待验收批次列表：按待移交、今日到馆、存在异常筛选；左侧列表独立滚动。
  - 清单验收面板：展示批次基本信息、提交人、预计日期、签字清单状态。
  - 文件上传与匹配区：拖拽 U 盘文件后展示文件名匹配结果、四性检查摘要、异常原因。
  - 条目验收表：逐条标记已接收或已回退，填写验收说明/回退原因；宽表格支持横向和纵向独立滚动，表头固定。
  - 回执预览区：展示已接收条目和回退条目，提供导出按钮。

## 5. 交互逻辑说明

1. 点击待验收批次行，加载批次详情和条目列表；顶部筛选标签可过滤待移交、今日到馆和存在异常清单。
2. 拖拽或选择 U 盘文件后模拟写入暂存文件，按清单中的档案文件名匹配条目。
3. 唯一匹配且检查通过时显示“匹配成功”；未匹配、重复、缺失、检查失败显示“匹配异常”。
4. 前台管理员可对异常文件执行人工确认、重新匹配或回退条目。
5. 点击“回退”必须填写回退原因，回退条目不进入后台入库。
6. 点击“确认接收”时，若全部条目接收则批次为已接收；存在回退条目则为部分接收。
7. 确认接收后可导出接收回执，回执包含已接收条目和回退原因。

## 6. 启发式自查记录

| 原则 | 自查结论 |
|------|----------|
| 系统状态可见性 | 批次状态、条目验收状态、文件匹配状态和回执状态可见。 |
| 现实世界匹配 | 使用纸质清点、U 盘、签字清单、回执、盖章等前台接待语言。 |
| 用户控制与自由 | 异常可人工确认或回退；确认接收前可修改验收说明。 |
| 一致性与标准 | 批次、条目、暂存文件状态与新版流程一致。 |
| 错误预防 | 回退必须填写原因；确认接收前显示异常数量。 |
| 识别而非记忆 | 上传区直接列出匹配结果和异常处理建议。 |
| 灵活性与效率 | 支持批量上传、批量标记纸质验收通过、可用筛选和左右/表格独立滚动。 |
| 美观与简约 | 页面按批次、上传匹配、条目验收、回执预览分区。 |
| 错误识别与恢复 | 未匹配、重复、缺失、检查失败均显示清晰原因。 |
| 帮助与文档 | 提示前台仅做验收和暂存，不生成正式档号。 |
