# 用户管理 - 原型设计

## 1. 页面概述

- 页面名称：用户管理
- 所属门户：管理后台
- 页面路径：`prototype/admin/user-management.html`
- 使用角色：系统管理员
- 设计依据：`new-doc/业务场景.md` 场景十四，`new-doc/数据库设计.md` 中 `organizations`、`fonds`、`users`、`roles`、`user_roles`、`audit_logs`。

## 2. 业务场景归属分析

本页面属于“系统管理员管理用户”场景，负责组织、全宗、用户、角色关系维护。系统管理员可以创建账号、分配预设角色、禁用账号、重置密码和维护数据范围，但不参与档案业务审批，不默认拥有档案正文或电子文件查看权限。

上游输入为组织、全宗和预设角色字典；页面内维护 `users`、`user_roles`、`organizations`、`fonds`；下游消费为登录鉴权、门户菜单、后端角色校验、密级上限和数据范围过滤。所有账号禁用、密码重置和角色变更都应写入 `audit_logs`。

涉及状态节点：

- 用户状态：`active`、`disabled`
- 用户类型：`internal`、`public`
- 数据范围：`own_org`、`own_fonds`、`all`
- 角色：`front_archivist`、`back_archivist`、`transfer_user`、`internal_reader`、`public_user`、`director`、`sys_admin`

## 3. 用户与操作分析

角色：系统管理员。

主路径操作：

- 创建新用户，填写姓名、账号、手机号、所属单位、部门和初始密码
- 选择一个或多个预设角色，写入 `user_roles`
- 维护组织和全宗基础信息
- 设置密级上限和数据范围
- 禁用账号或重置密码

异常路径操作：

- 登录名重复：阻止创建并提示唯一约束
- 用户离职或异常：禁用账号，保留历史业务记录和日志
- 角色与用户类型冲突：提示检查，例如公众账号默认只分配公众角色
- 系统管理员尝试处理业务审批：提示转到馆领导审批工作台，用户管理不替代审批

## 4. 页面布局说明

页面使用管理后台统一壳层。内容区分为用户概览、用户列表、账号编辑抽屉式区域、组织与全宗维护、角色关系和审计提示。

关键区域：

- 用户概览：内部账号、公众账号、禁用账号、系统管理员数量
- 用户列表：展示账号、姓名、单位、角色、数据范围、密级上限和状态
- 编辑区：维护账号基本信息、角色、数据范围和密级上限
- 组织/全宗：展示组织和全宗基础关系
- 权限边界：提示系统管理员不默认查看档案正文，不替代业务审批

## 5. 交互逻辑说明

点击“新建用户”清空编辑区并准备创建账号；点击“保存用户”模拟新增用户到列表；点击“禁用”将用户状态改为禁用；点击“重置密码”给出操作反馈；角色复选框用于模拟 `user_roles` 关系。

页面明确权限控制以后端接口鉴权为准，前端菜单隐藏不是安全边界。系统管理员维护角色和配置，但密级调整、开放调整、销毁审批仍由馆领导审批工作台处理。

## 6. 启发式自查记录

1. 系统状态可见性：用户状态、角色和数据范围可见。
2. 系统与现实世界匹配：使用组织、全宗、角色、密级上限等业务术语。
3. 用户控制与自由：保存前可修改，禁用和重置密码有明确反馈。
4. 一致性与标准：复用后台壳层、表格、表单和状态标签。
5. 错误预防：登录名唯一、角色冲突和业务审批边界有提示。
6. 识别而非记忆：角色代码和中文角色同屏展示。
7. 灵活性与效率：支持多角色勾选和常用筛选。
8. 美观与简约设计：用户、组织、全宗和边界说明分区展示。
9. 帮助用户识别和修复错误：异常路径提供明确提示。
10. 帮助与文档：权限边界和审计留痕在页面中说明。
