# 档案销毁 - 原型设计

## 1. 页面概述

- 页面名称：档案销毁
- 所属门户：管理后台
- 页面路径：`prototype/admin/destruction.html`
- 使用角色：档案管理员（后台）
- 页面目标：查看由鉴定批次自动生成的销毁清册，检查清册快照，提交馆领导审批；审批通过后执行销毁确认，保留清册、审批、销毁确认三类证据链。

## 2. 业务场景归属分析

- 所属业务场景：`new-doc/业务场景.md` 场景五“档案销毁”。
- 上游关系：档案鉴定完成后，系统为待销毁档案自动生成销毁清册和明细快照。
- 下游关系：提交审批后进入馆领导审批工作台；审批通过后清册进入待销毁列表；确认销毁后档案状态变为已销毁，电子文件按策略删除或标记删除。
- 涉及数据实体：`destruction_lists`、`destruction_items`、`approval_requests`、`business_attachments`、`archive_files`、`archives`、`audit_logs`。
- 关键字段：`list_no`、`list_name`、`appraisal_batch_id`、`status`、`approval_request_id`、`destroyed_at`、`destroy_method`、`supervisor_name_1`、`supervisor_name_2`、`destroy_note`、`archive_no_snapshot`、`title_snapshot`、`retention_snapshot`、`security_level_snapshot`、`appraisal_opinion_snapshot`、`file_delete_status`。
- 状态节点：销毁清册 `draft -> pending_approval -> approved -> destroyed`；正式档案 `pending_destruction -> destroyed`；审批单 `pending -> approved/rejected`。
- PlantUML 校准：`business-flow-destruction.puml` 明确“鉴定完成 -> 自动生成清册 -> 提交馆领导审批 -> 审批通过 -> 两名监销人现场核对销毁 -> 上传现场照片 -> 最终确认销毁 -> 永久保留元数据、清册、审批、日志”。

## 3. 用户与操作分析

- 档案管理员（后台）主路径操作：
  - 在“待提交”标签查看鉴定批次自动生成的销毁清册。
  - 检查清册内档案元数据快照和来源鉴定批次。
  - 提交馆领导审批，清册状态变为待审批。
  - 在审批通过后的“待销毁”标签打开清册。
  - 填写销毁时间、销毁方式、监销人 1、监销人 2、销毁说明，上传至少一张现场照片。
  - 通过最终不可逆确认后完成销毁。
- 档案管理员（后台）异常路径操作：
  - 审批退回后查看退回意见，修改说明后重新提交。
  - 未填写两个监销人或未上传现场照片时阻止确认销毁。
  - 最终确认前二次提醒“确认后档案状态不可恢复”。
- 操作结果：
  - 提交审批创建 `approval_requests`，清册状态变为 `pending_approval`。
  - 确认销毁后清册状态变为 `destroyed`，档案状态变为 `destroyed`。
  - 电子文件记录写入删除时间、执行人、哈希、原对象路径和删除状态。
  - 清册快照、审批记录、销毁确认、操作日志永久保留。

## 4. 页面布局说明

- 统一后台左侧导航和顶部栏。
- 顶部指标区展示待提交、待审批、待销毁、已销毁清册数量。
- 主体左侧为清册列表和状态标签；右侧为清册详情、快照明细和操作区。
- 快照明细表展示档号快照、题名快照、分类、保管期限、密级、鉴定意见、电子文件删除状态。
- 证据链区展示销毁清册、审批记录、销毁确认三类证据及生成节点。
- 确认销毁弹窗展示必填字段、照片上传占位和不可逆确认勾选。

## 5. 交互逻辑说明

- 点击清册列表切换右侧详情和操作按钮。
- “待提交”清册可点击“提交审批”，状态模拟变为待审批并显示提交成功提示。
- “待销毁”清册可点击“确认销毁”，打开销毁确认弹窗。
- 销毁确认弹窗必须填写销毁方式、两个监销人、现场照片，并勾选不可逆确认。
- 点击最终确认后展示“档案状态已更新为已销毁，证据链永久保留”的反馈。

## 6. 启发式自查记录

1. 系统状态可见性：清册状态、审批状态、电子文件删除状态和证据链状态可见。
2. 系统与现实世界匹配：使用清册、监销人、现场照片、审批记录、销毁确认等业务术语。
3. 用户控制与自由：提交审批前可检查快照；确认销毁弹窗可取消。
4. 一致性与标准：沿用后台统一导航、标签页、表格、状态标签和弹窗样式。
5. 错误预防：最终销毁必须二次确认，并说明不可逆后果。
6. 识别而非记忆：清册快照和证据链在同页展示。
7. 灵活性与效率：按待提交、待审批、待销毁、已销毁快速筛选。
8. 美观与简约设计：销毁页面聚焦清册、审批、确认和证据链，不展示无关正文。
9. 帮助用户识别、诊断并修复错误：缺少监销人或照片时有表单提示位。
10. 帮助与文档：页面内说明馆领导审批即批准凭证，证据永久保留。
