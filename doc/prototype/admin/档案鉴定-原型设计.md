# 档案鉴定 - 原型设计

## 1. 页面概述

- 页面名称：档案鉴定
- 所属门户：管理后台
- 页面路径：`prototype/admin/appraisal.html`
- 使用角色：档案管理员（后台）
- 页面目标：处理保管期限到期或即将到期档案，创建鉴定批次，逐件选择“延长保存”或“待销毁”，完成后记录鉴定意见并自动生成销毁清册。

## 2. 业务场景归属分析

- 所属业务场景：`new-doc/业务场景.md` 场景四“档案鉴定”。
- 上游关系：后台概览和统计研判提供到期提醒；正式档案表提供保管期限、到期日、分类、年度等筛选条件。
- 下游关系：鉴定为延长保存时更新保管期限并写入变更日志；鉴定为待销毁时正式档案进入 `pending_destruction`，系统自动生成销毁清册，供档案销毁页面提交审批。
- 涉及数据实体：`archives`、`appraisal_batches`、`appraisal_items`、`destruction_lists`、`destruction_items`、`archive_change_logs`、`audit_logs`。
- 关键字段：`batch_no`、`batch_name`、`category_id`、`formed_year_start`、`formed_year_end`、`status`、`completed_at`、`appraisal_result`、`new_retention_period`、`new_retention_until`、`opinion`、`appraised_by`、`appraised_at`。
- 状态节点：鉴定批次 `draft/completed`；正式档案 `normal -> pending_destruction`；销毁清册 `draft` 由鉴定完成自动生成。
- PlantUML 校准：`business-flow-destruction.puml` 明确系统检测到期档案、后台管理员创建鉴定批次、逐件鉴定、待销毁项自动生成销毁清册；`archive-state-machine.puml` 明确 `Normal -> PendingDestroy`。

## 3. 用户与操作分析

- 档案管理员（后台）主路径操作：
  - 查看到期提醒、待鉴定档案、草稿批次和已完成批次。
  - 创建鉴定批次，选择分类、年度范围、到期日期范围。
  - 将命中范围内的到期档案拉入批次。
  - 逐条选择“延长保存”或“待销毁”，填写鉴定意见。
  - 对延长保存项设置新的保管期限和新到期日。
  - 完成鉴定，系统生成销毁清册草稿。
- 档案管理员（后台）异常路径操作：
  - 未处理全部条目时阻止完成鉴定。
  - 延长保存未填写新期限或新到期日时提示补全。
  - 已借出或盘点中的档案可参与价值判断，但待销毁执行需在销毁页面核对实物和证据链。
- 操作结果：
  - 延长保存写入 `appraisal_items` 和 `archive_change_logs`。
  - 待销毁档案写入 `appraisal_items`，档案状态变为 `pending_destruction`。
  - 鉴定完成触发 `destruction_lists` 和 `destruction_items` 快照生成。

## 4. 页面布局说明

- 统一后台左侧导航和顶部栏。
- 顶部指标区展示即将到期档案、待鉴定批次、待销毁条目和已生成清册。
- 上方筛选/创建区用于新建鉴定批次，展示分类、年度范围、到期范围。
- 主体左侧为鉴定批次列表；右侧为批次明细表和逐件鉴定操作。
- 明细表展示档号、题名、分类、保管期限、到期日、当前状态、鉴定结果、意见。
- 完成区展示自动生成销毁清册的信息和清册快照说明。

## 5. 交互逻辑说明

- 点击“创建鉴定批次”打开弹窗；选择范围后更新命中数量和批次名称。
- 表格中“延长保存”和“待销毁”为互斥选择。
- 选择“延长保存”后显示新保管期限与新到期日输入；选择“待销毁”后显示待销毁状态标签。
- 点击“完成鉴定”后检查未处理项，模拟生成销毁清册并显示清册号。
- 页面明确说明鉴定完成后清册自动生成，销毁审批和最终确认在“档案销毁”和“审批工作台”完成。

## 6. 启发式自查记录

1. 系统状态可见性：到期提醒、批次状态、鉴定进度和清册生成状态可见。
2. 系统与现实世界匹配：使用保管期限、鉴定意见、保存价值、待销毁等档案处置术语。
3. 用户控制与自由：批次创建可取消，鉴定结果可在完成前修改。
4. 一致性与标准：复用后台统一导航、表单、状态标签和表格。
5. 错误预防：延长保存必须填写新期限；未处理条目不能完成。
6. 识别而非记忆：批次范围、到期日、原保管期限和结论在同一行展示。
7. 灵活性与效率：可按分类、年度、到期范围批量生成批次。
8. 美观与简约设计：页面聚焦价值判断和后续清册生成，不执行销毁确认。
9. 帮助用户识别、诊断并修复错误：未处理或缺字段时给出明确提示。
10. 帮助与文档：页面内说明“鉴定生成销毁清册”的业务结果。
