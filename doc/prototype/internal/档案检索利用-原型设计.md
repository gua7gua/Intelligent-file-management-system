# 档案检索利用-原型设计

## 1. 页面概述

- 页面名称：档案检索利用
- 所属门户：内部查阅者门户
- 页面路径：`prototype/internal/search.html`
- 使用角色：内部查阅者
- 页面目标：内部查阅者通过结构化条件或 AI 自然语言转 JSON 条件检索权限范围内档案，并进行预览、下载或发起纸质借阅申请；结构化条件覆盖档号、题名、责任者、全宗、来源、载体、状态、标签和电子文件属性。

## 2. 业务场景归属分析

- 所属业务场景：场景九“内部人员检索利用档案”，关联场景八“借阅审批”。
- 上游输入：用户自然语言、结构化检索条件、当前用户角色/密级/单位/全宗范围。
- 下游消费：普通检索接口返回权限过滤后的档案；电子文件预览/下载走同一鉴权；纸质借阅申请写入 `borrow_requests`。
- 涉及实体：`archives`、`archive_files`、`archive_tags`、`archive_access_logs`、`borrow_requests`、`users`。
- 状态节点：正式档案仅返回生命周期为正常且不在销毁状态的权限内档案；纸质借阅申请生成后为待审批；借阅不改变档案状态，出库后才变为借出。

## 3. 用户与操作分析

- 内部查阅者主路径：输入 AI 自然语言；生成查询 JSON；填充表单；确认检索；查看结果；打开详情；预览/下载电子文件；申请纸质借阅。
- 内部查阅者异常路径：AI 不可用时手工检索；JSON 格式错误时提示；权限不足档案不出现在结果中；纸质未上架或盘点中不可申请。
- 操作结果：查询、日志记录、借阅申请提交；不直接审批，不显示架位。

## 4. 页面布局说明

- 统一内部壳层：左侧导航、顶部栏、内容区。
- 查询区：自然语言 AI 输入、JSON 结果、分组结构化条件表单，包含核心元数据、时间与业务属性、电子文件与排序三组。
- 结果区：档号、题名、分类、密级、载体状态、可预览/可下载/可借阅状态。
- 结果区和详情区支持独立滚动；长结果列表不挤压右侧详情审查。
- 详情抽屉：元数据、电子文件状态、借阅申请表单；不展示库房和架位。

## 5. 交互逻辑说明

- AI 输入点击“生成 JSON”后只生成结构化查询条件，不直接查库。
- “填充表单”将 JSON 字段填入关键词、档号、题名、全宗、年度范围、责任者、来源、载体状态、保管期限、密级范围、电子文件和排序等筛选项。
- “确认检索”模拟调用普通检索接口，并提示后端按密级、单位、全宗范围硬过滤。
- “预览”和“下载”均模拟重新鉴权并记录访问日志。
- “申请借阅”打开申请表单，提交后生成待审批借阅申请；页面不显示具体架位。

## 6. 启发式自查记录

1. 系统状态可见性：AI JSON、过滤条件、权限过滤结果和借阅申请状态可见。
2. 系统与现实世界匹配：使用档号、题名、责任者、形成年度、密级等档案术语。
3. 用户控制与自由：AI 结果可填充、复制、手工调整，不自动检索。
4. 一致性与标准：复用内部壳层、表单、表格、抽屉、状态标签。
5. 错误预防：AI 不查库、不读正文、不绕过权限；架位隐藏。
6. 识别而非记忆：JSON 与表单并列展示，用户可确认条件。
7. 灵活性与效率：支持自然语言和分组高级条件两种检索方式，结果表格和详情区可独立滚动。
8. 美观与简约设计：结果列只展示查阅者需要的利用信息。
9. 帮助用户识别错误：JSON 错误、无权限、不可借阅均有提示。
10. 帮助与文档：边界提示说明预览下载鉴权和纸质借阅流程。
