# 征集清单-原型设计

## 1. 页面概述

- 页面名称：征集清单
- 所属门户：公众门户
- 页面路径：`prototype/public/collection.html`
- 使用角色：社会公众
- 页面目标：公众填写捐赠意向和征集清单条目，提交后进入后台联系判断流程。

## 2. 业务场景归属分析

- 所属业务场景：场景二“社会征集与捐赠”。
- 上游输入：公众账号信息来自 `users`；公众填写清单级字段和条目字段；浏览器本地解析文件名、扩展名和大小。
- 下游消费：提交后写入 `intake_batches(source_type = collection)` 和 `intake_items`，状态从草稿进入待联系；后台管理员在 `admin/collection.html` 联系判断。
- 涉及实体：`intake_batches`、`intake_items`、`users`、后续 `business_attachments`。
- 状态节点：草稿 -> 待联系；后续由管理员流转到待接收、已拒绝、已接收、部分接收；公众提交后不可编辑。

## 3. 用户与操作分析

- 社会公众主路径：填写清单标题、捐赠人、联系电话；新增清单条目；拖拽或选择电子文件解析文件名；提交捐赠意向。
- 社会公众异常路径：必填字段缺失时提示；待处理清单达到限制时提示不可继续提交；提交后尝试编辑时提示只读。
- 操作结果：保存草稿不改变提交流程；提交后批次状态为待联系；不上传电子文件本体。

## 4. 页面布局说明

- 顶部导航：公众门户统一顶部导航，当前页高亮“征集清单”。
- 页面头部：流程阶段和业务边界提示。
- 左侧主体：清单级表单、文件名解析区、条目表格。
- 右侧辅助：目标属性、数量限制、状态流转、提交结果。
- 底部操作：保存草稿、提交捐赠意向、返回公众概览。

## 5. 交互逻辑说明

- 文件选择或拖拽只在浏览器中读取 `File.name`、扩展名和大小，自动生成条目，不调用上传接口。
- 条目载体状态由公众选择或确认，不由文件动作自动推断。
- 提交前校验清单标题、捐赠人、联系电话和至少一个条目。
- 提交后页面状态改为“待联系”，表单和条目编辑控件禁用；公众端只能查看结果。
- 征集档案目标属性固定展示为永久、无密级、公开，但必须管理员接收、协议确认、后台入库后才进入公开利用范围。

## 6. 启发式自查记录

1. 系统状态可见性：当前草稿/待联系状态、条目数量和提交结果明确展示。
2. 系统与现实世界匹配：使用捐赠人、联系电话、档案标题、载体状态等业务术语。
3. 用户控制与自由：提交前可新增、删除、编辑条目；保存草稿不提交。
4. 一致性与标准：复用公众导航、表单、按钮、表格、状态标签。
5. 错误预防：必填校验、数量限制提示和提交后只读防止误改。
6. 识别而非记忆：目标属性、流程阶段和字段说明在同页可见。
7. 灵活性与效率：支持手工新增和文件名批量解析两种录入方式。
8. 美观与简约设计：主体聚焦清单提交，不放后台验收和入库字段。
9. 帮助用户识别错误：缺字段、无条目、只读操作均有明确反馈。
10. 帮助与文档：简短说明征集公开生效边界和到馆接收要求。
