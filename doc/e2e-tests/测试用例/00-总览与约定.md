# 00 · 总览与约定

> 本目录是「智能档案管理系统」前端的 **Playwright E2E 测试套件**（含用例文档与自动化代码）。
> 用例文档是人类可读的设计来源，`tests/` 是其自动化实现，两者一一对应、命名前缀一致。

---

## 一、套件定位

- **真实集成测试**：连真前端（`http://localhost:3000`）+ 真后端（`http://localhost:8080`），**非 mock**。AI / ClamAV / MinIO 均真实启用，仅短信降级（固定码 `123456`）。
- **目标**：以真实用户视角驱动浏览器，覆盖 4 个门户（public/internal/transfer/admin）的页面级冒烟、异常路径，以及跨角色业务闭环。聚焦"用户实际使用的测试"，深入前端每一处细节。
- **节奏**：阶段一（冒烟 + 异常路径）先行，阶段二（7 条业务闭环 E2E）在其稳定后扩展。

## 二、前置条件

1. 前后端服务在跑：前端 `cd frontend && npm run dev`（3000）；后端 `cd backend && ./mvnw spring-boot:run -Dspring-boot.run.profiles=dev`（8080）。
2. DB 可为任意基线（**幂等设计，不重置 DB**，详见 §五）。
3. 浏览器：复用系统已装的 `google-chrome-stable`（`channel: 'chrome'`），无需下载浏览器二进制。

## 三、目录结构

```
doc/e2e-tests/
├── playwright.config.ts      # channel:chrome / baseURL:3000 / serial / globalSetup
├── global-setup.ts           # 探活 + 为各角色 API 登录生成 storageState
├── support/
│   ├── env.ts                # BASE_URL / API_BASE / 密码 / 运行戳
│   ├── accounts.ts           # 8 账号 + role→portal→默认路由 + storageState 路径
│   ├── auth.ts               # loginByApi / saveAuthFile / fetchMe
│   ├── fixtures.ts           # 夹具绝对路径 + uniqueTitle（幂等前缀）
│   ├── expect.ts             # 体感断言（非英文枚举 / 非 ISO 时间 / 可见可点）
│   └── pages/                # 轻量页面对象（POM），每页一个文件
├── tests/
│   ├── 00-login/             # 登录与鉴权（UI 登录 + 错密码）
│   ├── smoke-public/         # 公众门户冒烟（按页面拆）
│   ├── smoke-internal/       # 内部门户冒烟
│   ├── smoke-transfer/       # 移交门户冒烟
│   ├── smoke-admin/          # 管理后台冒烟（按页面/主题拆）
│   └── error-paths/          # 异常路径
└── 测试用例/                  # 本目录：人类可读用例文档
```

**结构原则（避免单脚本过长）**：spec 按「一页面 / 一主题」拆文件；重复交互抽进 `support/pages` POM；体感/字段对照断言抽进 `support/expect`。

## 五、幂等约定（可重复运行）

- 写操作（捐赠标题、移交清单标题、编研标题等）一律加运行戳前缀：`support/fixtures.ts#uniqueTitle` → `PW<时间戳>-<标签>`。
- 断言只针对「本次创建」的对象（按前缀/本次产出的编号），不依赖固定档号/批次号。
- **不重置 DB**：同一库反复跑会累积测试数据，但不影响功能验证与断言。

## 六、定责口径（沿用第三轮测试计划）

| 类 | 含义 | 处理 |
|---|---|---|
| **A** | 后端返回正确，前端用错/渲染错 | 前端 |
| **B** | 后端返回正确，前端逻辑合理却仍异常 | 前端（深挖） |
| **C** | 后端返回 ≠ 文档，契约不变 | 后端 |
| **D** | 文档/设计本身缺陷，需改契约 | 暂停摆方案，方江苏拍板 |

E2E 只负责**暴露问题**（失败即记现象 + 复现 + 定责初判），**不擅自改产品代码**；发现的问题回填到第三轮问题记录或单独 issue。

## 八、方法论（沿用第三轮，转化到自动化）

1. **业务闭环驱动 + 换输入**：不只点第一行/第一个对象，验证点换不同行/清空再填。
2. **异常路径强制**：错密码、空提交、越权、跨组织、搜非公开——每个表单至少覆盖一类。
3. **字段对照**：列表/详情展示字段 vs 后端 Response DTO，前端漏显的逐个判「该不该显」。
4. **体感转断言**（`support/expect`）：关键元素可见且不被遮挡；文案不含原始英文枚举（`pending_archive` 等）；时间非 ISO。
5. **web-first 断言**：用 `expect(locator).toBeVisible()` 等自动重试断言，AI 异步环节用 `expect.poll` 轮询，避免硬 `sleep`。

## 九、选择器约定

- 优先 **role / 可见文本**（`getByRole`、`getByText`），次选 id/class。
- Element Plus 下拉：先 `click()` 触发，再于 `.el-select-dropdown__item` 中按文本点选（下拉 teleport 到 body）。
- 暂不要求产品代码加 `data-testid`（避免侵入；如后续选择器频繁失效，再推动加）。

## 十、运行方式

```bash
cd doc/e2e-tests
npm install                 # 首次
npm test                    # 跑全部
npx playwright test tests/00-login       # 只跑登录
npx playwright test tests/smoke-public   # 只跑公众冒烟
npx playwright test --headed             # 有头模式看执行
npm run report              # 打开 HTML 报告
```

失败自动截图 + trace（`on-first-retry`），报告在 `playwright-report/`。
